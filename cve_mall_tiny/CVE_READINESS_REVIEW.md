## 3. 最强证据

1. **源代码直接确认 java.util.Random 的使用**
   - `UmsMemberServiceImpl.generateAuthCode()` 使用 `Random`
   - 6位纯数字验证码仅有 1,000,000 种可能

2. **验证码在 API 响应中直接返回**
   - `CommonResult.success(sb.toString())` 明文返回
   - 验证码安全价值降低

3. **多层安全缺陷叠加**
   - 无速率限制、无尝试次数限制、代码中未见过期时间设置

## 8. 是否存在重复 CVE 风险

**重复风险低**

已知 mall-tiny CVE（CVE-2024-57432 ~ CVE-2024-57435）均为不同漏洞类型：
- CVE-2024-57432: JWT 签名密钥硬编码 / JWT 可伪造 / 认证绕过
- CVE-2024-57433: logout 后 token 仍有效 / 访问控制问题
- CVE-2024-57434: 默认测试用户具有超级管理员权限 / 默认高权限账号问题
- CVE-2024-57435: resource 创建接口空数据导致空指针异常，进而造成 DoS

**无 CWE-338 / 验证码明文返回 / 验证码机制相关的 CVE。**

但仍需通过 GitHub Security Advisory 联系维护者确认是否已有私密报告。
